AudioPlaybackKit 0.13.0 fixes WavPack and Xing-less MP3 seeking, ends a WavPack stream of unknown length
cleanly, lets an `ItemSource` change format mid-item, makes `PlayerEvent` carry the item it names, and adds
`NowPlayingSession.refreshMetadata()` and a recipes section in the docs.

This is a minor bump at 0.x: it changes public API (below) and the PCM some seeks land on. Linear decode
is bit-identical to 0.12.0: the two conformance goldens that changed hold seek landings only.

- **WavPack seeks** (#175, 3772227) land sample-exactly where they threw `AVERROR_INVALIDDATA` before
  (`wavpack_stereo.wv` at 2.667 s and 3.9 s; the golden gains those seeks, nothing else moves).
- **Xing-less VBR MP3 seeks** (#169, 7376e13) anchor on mp3dec's packet index within the read range.
  `bear-vbr-no-seek-table.mp3` seeked to 1.872 s now lands sample-aligned (`alignFrames` 0, was -896), and
  a seek to the end lands at 2.808 s (was 2.678).
- **A WavPack stream of unknown length** (#176, 0da4dc8) ended in failure at its trailing APE tag, which
  FFmpeg read as a block header; it now ends at EOF. The seek-to-end and seek-count symptoms shared the
  cause, and the three WavPack known-issue rules are gone.

Moving Shuttle Podcasts or Shuttle2 over: [docs/migrating.md](https://github.com/timusus/AudioPlaybackKit/blob/0.13.0/docs/migrating.md#migrating-from-012-to-013).

## What changed

- **`PlayerEvent` names its item** (#180). `itemFailed`, `seekLanded`, `seekAdjusted`, `firstAudioRendered` and
  `bufferingStarted` take a `PlayerEvent.ItemRef` (`index`, `item`) in place of the index, and `itemTransition`
  takes one per side, captured when the event is sent. The event stream yields later, so `player.items[index]`
  could be out of range or another item after an edit. Removing the current item sends it as `from`.
- **Format changes mid-item** (#181, [ADR-0025](https://github.com/timusus/AudioPlaybackKit/blob/0.13.0/docs/decisions/0025-output-format.md)).
  `ItemSource.currentFormat` (default nil) lets a source report a rate or channel change after `open()`, as a
  stream re-opened at a time offset can. The transport drains the processors, reconfigures them with the same
  item and flushes, then sends `TransportEvent.formatChanged(item:format:)`; `Player.audioFormat` follows.
  `crossed` reports the format its first audio was heard in. Frame positions are mapped to seconds per
  segment, so position stays continuous across a change and after a seek or a re-feed that lands in another format.
- **`AudioProcessingPipeline`** (#182, 50fd95e). A trim ending exactly on a chunk's last frame no longer lets the
  frames that follow be dropped with its placeholder tag; the item failed with `misreportedFrames`.
- **`NowPlayingSession.refreshMetadata()`** republishes the current item's title, artist, album, artwork and
  duration after the app edits its tags. A refresh checks the shown info before it loads, so refreshes racing
  each other, an item change or the first artwork lose to the newer state.
- **MP3 seek labels.** An estimated landing's label range is untrusted per landing, and the label of a landing
  frame that is never fed no longer anchors a later index seek (#169).
- **Streaming.** A range-ignored 200 compares every covered range it overwrites, not the first
  (2d5026f). Tests now pin a seek to the end after the download finished sending no request, a `Content-Length`
  that disagrees with `Content-Range` keeping the range's total, files deleted under a reading source neither
  crashing nor hanging it, and a seek to the end after a partial read keeping the duration.
- **Player tests** pin that playback starts at half a second buffered for local and streamed items and that an
  underrun is reported only once everything written has been heard.
- **Recipes** ([docs/recipes](https://github.com/timusus/AudioPlaybackKit/blob/0.13.0/docs/recipes/README.md)):
  play a file, stream a URL with resume, a gapless queue with seeking and progress, the lock screen and remote
  commands, handling errors by category, testing app code with the fakes, and writing an `AudioProcessor`. Each
  is a test in the `RecipesTests` target, so it runs offline and cannot drift from the API.

## Breaking changes

- `PlayerEvent`'s `itemFailed`, `seekLanded`, `seekAdjusted`, `firstAudioRendered` and `bufferingStarted` carry an
  `ItemRef`, and `itemTransition`'s `from` and `to` are `ItemRef?`. Code that binds the index as an `Int` or
  indexes `items` with it no longer compiles; code that discards it does.
- `TransportEvent` has a new case, `formatChanged(item:format:)`: an exhaustive `switch` no longer compiles.
- Seeks into a Xing-less VBR MP3 or a WavPack file land on different frames than in 0.12.0.

Additive and source-compatible: `ItemSource.currentFormat` (defaulted; a wrapper should forward it) and
`NowPlayingSession.refreshMetadata()`. A processor may now be configured a second time within an item.

## Upgrading

[docs/migrating.md](https://github.com/timusus/AudioPlaybackKit/blob/0.13.0/docs/migrating.md#migrating-from-012-to-013)
lists each symbol and the call sites in both apps. Shuttle Podcasts compiles unchanged; Shuttle2 rewrites
`KitAudioPlayer.item(of:in:)` and can drop its `onEvent` hook. Both apps' `ItemSource` wrappers should forward
`currentFormat`.
