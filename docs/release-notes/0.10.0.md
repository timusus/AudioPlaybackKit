AudioPlaybackKit 0.10.0 adds a player. `Player` plays a list of your items with the audio session handled,
and `NowPlayingSession` puts it on the lock screen. It is also the first tag with the render layer: 0.9.0
was never tagged, so this release carries everything since 0.8.0.

This is a minor bump at 0.x: it adds products and changes decoder PCM for sources above stereo.

Moving Shuttle Podcasts or Shuttle2 over: [docs/migrating.md](https://github.com/timusus/AudioPlaybackKit/blob/0.10.0/docs/migrating.md). Before relying on the
release, run [docs/device-checklist.md](https://github.com/timusus/AudioPlaybackKit/blob/0.10.0/docs/device-checklist.md) on a phone; no test covers it.

## New products

- **`PlaybackPlayer`**: `Player<Item>` ([ADR-0019](https://github.com/timusus/AudioPlaybackKit/blob/0.10.0/docs/decisions/0019-player.md)). The item list and its
  edits, `state`, `position`, `duration` and `discontinuityCount` as `@Observable` properties, `events`,
  seeks across items, gapless advance, `repeatMode`, `pauseAtEndOfItem`, `rate`, `volume`, processors,
  and the `AVAudioSession` rules: lazy activation, interruptions with and without resume, route loss,
  media-services reset. A failed item stops with `itemFailed`; a recovery lands paused.
- **`PlaybackNowPlaying`**: `NowPlayingSession` binds a `Player` to `MPNowPlayingInfoCenter` and
  `MPRemoteCommandCenter`, with skip intervals or next and previous, rates, and async artwork.
- **`PlaybackPlayerTestSupport`**: `PlayerTestRig` and `FakeAudioSession`, a `Player` on a fake output
  and manual clock for an app's own tests.
- **`PlaybackRender`** and **`PlaybackRenderTestSupport`**: `Transport`, the gapless
  `AVSampleBufferAudioRenderer` output layer with `AudioProcessor` effects, and the fakes to test it
  ([ADR-0018](https://github.com/timusus/AudioPlaybackKit/blob/0.10.0/docs/decisions/0018-render-layer.md)). New since 0.8.0; `Player` is built on it.

## Breaking changes

Against the last tag, `PlaybackRender` and its API are new, so these break only code written against the
render layer on `main` since 0.8.0:

- `TransportEvent` has two new cases, `.recovered` (the output was rebuilt after a renderer failure or a
  media-services reset, and is paused at the heard position) and `.sought(item:seconds:applied:)` (every
  `setCurrent` and `seek` is answered, and `applied` says whether events before it are stale). An
  exhaustive `switch` over `TransportEvent` no longer compiles.
- `Transport` takes seconds: `setCurrent(item:source:startSeconds:)` and `seek(item:toSeconds:)`, and
  `.position(item:seconds:duration:)` carries the duration in seconds. The frame-based start and seek are
  gone. Store resume points in seconds; the seek converts at the item's own rate once it opens.
- A failing pre-armed next item no longer pauses the current one; it is dropped and reported as
  `.failed`, and the heard item's failure still pauses.

Behaviour changes in the decoder and streaming products:

- A read past the end of a body fails at once with `transport("out_of_range ...")`, as media3's
  `DefaultHttpDataSource` does, with no retry. A seek past the frontier of a range-ignoring body of unknown
  length is refused.
- Decoding of stereo and mono sources is unchanged; more than two channels is below.

## Decoder PCM change

With no `setOutputFormat` layout, a source of more than two channels whose layout is not FFmpeg's default
for that channel count is now remapped to the default order, so what the render layer
labels is what is in the buffer. Stereo and mono output, and every committed
conformance golden, are bit-for-bit unchanged.

## Also in this release

- Streaming: read-ahead can be given in seconds (`GrowingFileReadAhead(seconds:fallbackBytes:)`, with
  `streamProbed(duration:)`); MP3 with zero padding, RIFX WAV and more QuickTime first atoms are sniffed; a
  64 KiB overlap is verified at every join of a resumed download.
- Decode: `interrupt()` and `cancel()` are atomic in the C layer, and an interrupt aimed at a seek survives
  the seek's clear.
- Conformance: media3's FLAC and Matroska (ALAC, FLAC, Opus) fixtures are ported with committed goldens.
