AudioPlaybackKit 0.21.0 tells the source factory where playback starts, and keeps a seek that arrives
while an item is loading instead of refusing it.

This is a minor bump at 0.x: it changes public API (below). Decode and the PCM played are unchanged.

Moving Shuttle Podcasts or Shuttle2 over: [docs/migrating.md](https://github.com/timusus/AudioPlaybackKit/blob/0.21.0/docs/migrating.md).

## What changed

- **The factory gets the start position.** `ItemSourceFactory<Item>` is now
  `(Item, _ startPosition: TimeInterval) throws -> any ItemSource`. `Player` passes the position it loads
  at and 0 for a gapless next item, so a server transcode can open at the resume point in one request
  rather than at 0 and again at the position. The transport still seeks the source to that position
  afterwards; a source opened there treats the seek as a no-op.
- **A seek during a load is kept.** `Player.availableCommands` offers seeking (and so
  `changePlaybackPosition`, skip forward and back) until a source says it cannot seek, not only after it
  opens. A CarPlay or lock-screen scrub while the item loads is applied when the source answers, the
  latest one winning, and the previous item is not heard after it. This differs from media3, which greys
  seeking out until the item is ready. Skip next and previous already acted at once during a load.
- Test support: `FakeItemFactory.make(_:startPosition:)` records `starts`; `PlayerTestRig` still takes a
  one-argument factory closure.
