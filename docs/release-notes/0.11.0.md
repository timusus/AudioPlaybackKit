AudioPlaybackKit 0.11.0 lets an app put its own command policy between the lock screen and `Player`,
plays a seekable item of unknown length as seekable rather than live, and tells a processor which item
its frames belong to. Processors now rewrite audio in place, `Player` gains media3's `prepare()`,
`audioFormat` and pause-at-end semantics, and its state no longer reports a stale item or `.ready` before
audio arrives. It also adds test support for an app's own coordinator and Now Playing tests.

This is a minor bump at 0.x: it changes public API (below). Decoder PCM is unchanged.

Moving Shuttle Podcasts or Shuttle2 over: [docs/migrating.md](https://github.com/timusus/AudioPlaybackKit/blob/0.11.0/docs/migrating.md).

## What changed

- **Now Playing drives a protocol** (#141, [ADR-0020](https://github.com/timusus/AudioPlaybackKit/blob/0.11.0/docs/decisions/0020-now-playing-drives-a-protocol.md)).
  `NowPlayingSession` drives `NowPlayingControllable`, which `Player` conforms to. An app wraps the player
  in a `ForwardingNowPlayingControllable` and declares only what it changes: `availableCommands` greys a
  command out (a press racing the change gets `.commandFailed`), and `skipIntervals`, per item, picks skip
  buttons over next and previous. Previous is `seekToPrevious()`, which restarts an item with nothing
  before it.
- **Sources declare seekability** (#142, [ADR-0022](https://github.com/timusus/AudioPlaybackKit/blob/0.11.0/docs/decisions/0022-source-declared-seekability.md)).
  `ItemSource.isSeekable` defaults to having a duration. A source with no length that seeks, such as a
  server transcode re-opened at a time offset, is no longer live: the scrubber and seek commands are
  offered. A clamped, refused or inexact seek is reported as `PlayerEvent.seekAdjusted`; a seek is
  never dropped silently and never fails the item for being unseekable.
- **A processor's flush names the item** (#143, [ADR-0021](https://github.com/timusus/AudioPlaybackKit/blob/0.11.0/docs/decisions/0021-processor-stream-metadata.md)).
  `flush(_ metadata: StreamMetadata)` carries the app's item and its media frame, and the pipeline is
  drained and flushed at every item change, so a ReplayGain processor picks the track's gain there. The
  next item already opens ahead of the join, so a blocking URL resolve in `open()` overlaps the current
  item's tail, and a next item still opening can be withdrawn: `Transport.setNext` and `clearNext`
  interrupt its open.
- **Processors work in place** (#149, [ADR-0026](https://github.com/timusus/AudioPlaybackKit/blob/0.11.0/docs/decisions/0026-in-place-processing.md)).
  A stage that maps each frame to one frame implements `process(_:)` over an
  `UnsafeMutableBufferPointer<Float>` and rewrites the chunk with no copy. A stage that drops, adds or
  holds back frames conforms to `BufferingAudioProcessor`, which keeps the old queue shape.
- **Pause at end stays on the finished item** (#148, [ADR-0023](https://github.com/timusus/AudioPlaybackKit/blob/0.11.0/docs/decisions/0023-pause-at-end-stays-on-the-item.md)),
  as media3's `pauseAtEndOfMediaItems`: `.ready` at the item's duration; `play()` moves to the next
  item, a seek stays on the finished one.
- **`prepare()`** (#147, [ADR-0024](https://github.com/timusus/AudioPlaybackKit/blob/0.11.0/docs/decisions/0024-prepare.md)), as media3: from `.idle` (stopped or failed) it
  loads the current item at `position`, playing if `playWhenReady`. Retry after a failure is
  `prepare()`; skipping a failed item stays the app's call in its `itemFailed` handling.
- **`Player.audioFormat`** (#150, [ADR-0025](https://github.com/timusus/AudioPlaybackKit/blob/0.11.0/docs/decisions/0025-output-format.md)), as media3's `getAudioFormat()`:
  the heard item's decoded format, the one its processors run at. Nil until the item is heard; it
  changes when the join into the next item is heard.
- **State is honest across loads and restarts** (#145, #151). A load, skip or seek reports `.buffering`
  until the transport answers, so `state` never shows the previous item. A seek or recovery restart
  reports `.buffering` until its first audio is written, paused or playing, then `.ready`.
- **Streaming**: a resume from byte 0 accepts a 200 carrying the whole file, as it is the same request.

## Breaking changes

- `AudioProcessor` requires `process(_ samples: UnsafeMutableBufferPointer<Float>)`, and
  `queueInput`, `getOutput`, `queueEndOfStream` and `isEnded` move to `BufferingAudioProcessor`.
  **Upgrade:** a 1:1 stage (gain, EQ, limiter) moves its per-sample loop into `process(_:)` and deletes
  its queue; a stage that changes length (skip-silence, a resampler) changes its conformance to
  `BufferingAudioProcessor` and is otherwise unchanged. An in-place stage may not change the format.
- `TransportEvent.crossed` is `crossed(item:format:)`: a pattern `.crossed(let item)` needs `let format`.
- `AudioProcessor.flush()` is `flush(_ metadata: StreamMetadata)`. A processor that needs no metadata
  ignores the argument.
- `NowPlayingSession`'s `skipMode` and `SkipMode` are gone. Declare `skipIntervals` on a
  `ForwardingNowPlayingControllable` wrapper.
- `NowPlayingSession.init(player:...)` takes `any NowPlayingControllable<Item>`; a `Player` still passes.
- `ItemSource` has `isSeekable`, with a default. A source of no duration that seeks must return true.
- `PlayerEvent.seekAdjusted(index:requested:position:)` is new: an exhaustive `switch` over `PlayerEvent`
  no longer compiles. `TransportEvent.position` carries `isSeekable`, so a pattern over it needs one more
  field.
- `Player.isLive` is computed (neither seekable nor of known duration), and `Player.isSeekable` is new.

## Behaviour changes

- Processors flush at every join, gapless ones included: filter memory and a limiter's envelope reset
  there, as they did only at a format change. Audio a stage holds back is drained at the join, not lost.
- `Transport.setNext` and `clearNext` withdraw a next item still opening, interrupting its open.
- A seekable item of unknown length is not live: `NowPlayingSession` shows it with the metadata's
  duration if any, and enables the scrubber.
- `pauseAtEndOfItem` stays on the finished item instead of landing paused on the next; `play()` from
  there advances. An app that expected the next item current after the pause must call `play()` or
  `skipToNext()`.
- A paused seek, recovery or load reports `.buffering` until its audio is written, where it reported
  `.ready` at once; a load, skip or seek reports `.buffering` before the transport answers.
- A pause made by `pauseAtEndOfItem` is seen as `PlayerEvent.playWhenReadyChanged(false, reason: .endOfItem)`.

## New API

- `Player.prepare()`, `Player.audioFormat: PCMFormat?` and `BufferingAudioProcessor`.
- `RemoteCommand` and `RemoteCommandEvent` are public, naming the lock-screen commands.
- `PlaybackPlayerTestSupport` exports `FakeItemFactory<Item>`, which makes items scripted to fail, fail to
  open, fail a seek, end early, stall, or be live, unseekable or of unknown length, and records which
  were made. `PlayerTestRig.onEvent` sees each `PlayerEvent` as it is sent, with no task to drain.
- **`PlaybackNowPlayingTestSupport`** (new product): `FakeNowPlayingInfoCenter`, `FakeRemoteCommandCenter`
  and a `NowPlayingSession` initialiser taking them, for an app's tests to press commands and read what
  is shown; `settle()` waits for the session's pending refresh.
- `FakeItemFactory.formats` decodes chosen items at their own format.

## Test support changes

The loopback server's fault knobs are gates a test opens and closes, not durations (#153), so a loaded
simulator cannot stretch a fault window:

- `LoopbackMediaServer.refuseRequests(for:)` is `refusesRequests: Bool`; set it false to end the outage.
- `outageAfterClose` is a `Bool`: the drop turns `refusesRequests` on until the test turns it off.
- `answerWithPage` holds the rest of the body until `releaseHeldBody(forRangeStartingAt:)`.
- `stop()` returns once the listener is cancelled and its port is free; it may be called twice.
- The server binds `127.0.0.1` with no port reuse (#146): on the iOS simulator a wildcard bind could
  take a port a host process held on loopback.
- `SourceStall.wasReleased` reports the release without a wait.
- docs/usage.md describes testing an app against these products (#152).

## Upgrading from 0.7.x

Shuttle2 pins 0.7.x. There are no 0.8.0 notes; [0.10.0's](0.10.0.md) cover the release before this one.
Besides the breaks above, these moved between 0.7.2 and 0.10.0:

- A read past the end of a body fails at once with `transport("out_of_range ...")`, with no retry, as
  media3's `DefaultHttpDataSource` does.
- A seek past the frontier of a range-ignoring body of unknown length is refused.
- A source of more than two channels whose layout is not FFmpeg's default for its count is remapped to
  the default order, and the render layer labels the channels in that order. Stereo and mono are unchanged.
- Every request that joins bytes already downloaded asks for up to 64 KiB of them again and compares
  them with the file; a mismatch discards the file and restarts at the reader's position (ADR-0016).
